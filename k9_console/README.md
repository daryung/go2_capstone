# K9 Console — 실제 로봇 관찰·기록 로컬 웹앱

기준 디자인: https://k9-console-daryung.equalwand34.chatgpt.site/
같은 배치와 색상, 조종 패널을 사용하며 시뮬레이션 버튼·가상 데이터는 포함하지 않습니다.
실제 연결되지 않으면 영상·탐지·기록·요약 결과를 만들어 표시하지 않습니다.
공개 사이트의 원격 서버가 로봇을 조종하는 구조가 아닙니다. Python을 PC에서 실행하고 로컬 페이지를 사용합니다.

## 1. 실행

압축을 go2_capstone 아래에 풀어 k9_console 폴더로 둡니다.
기존 WebRTC 조종에 성공했던 .venv와 GO2_AES_KEY 환경변수를 그대로 사용하세요.
기존 vision.py, manual_control.py, keyboard_control.py는 모두 종료하고 이 앱만 실행합니다.

```bash
cd k9_console
python -m pip install -r requirements.txt
python app.py
```

브라우저에서 **http://127.0.0.1:8000** 을 엽니다. localhost 대신 안내된 주소를 사용하세요.
시작만으로 로봇이 연결되거나 움직이지 않습니다. 화면에서 IP를 확인하고 [연결]을 누릅니다.
PC와 로봇은 같은 Wi-Fi에 있어야 합니다.
다른 포트는 `python app.py --port 8001`.

Flask, pygame은 필요 없습니다. 기존 unitree_webrtc_connect를 강제 업그레이드하지 않습니다.
원래 connection(3).py 기반 연결 클래스를 robot/connection.py에 포함했습니다.
AES 키는 코드·브라우저·공유 ZIP에 넣지 않습니다. 키 미설정은 명확한 오류로 표시됩니다.

## 2. 수동 조종

- 마우스로 이동 버튼을 누르는 동안 이동, 놓으면 정지 요청
- 입력칸·버튼 밖을 클릭하고 왼쪽 Shift + W/S/A/D, Q/E로 조종
- Space 정지 요청, 포커스 이탈·명령 갱신 0.4초 만료 시 정지 요청
- 이동 설정 0.1~0.4m/s, 회전 0.3rad/s
- 대각 이동 합성 속도도 최대 설정값으로 제한
- MCF 또는 normal을 조회하고 해당 명령표 사용, 자동 모드 전환 없음
- 일어서기/엎드리기는 별도 버튼. 자세 전환 중 이동 명령은 차단

실제 정지 여부를 네트워크 명령 전송으로 보장하지 않습니다. 통신 단절·프로세스 중단에서는 정지가 전달되지 않을 수 있습니다.
물리 리모컨 정지를 준비하고 통제된 모의 현장에서 낮은 속도로 시험하세요.
자동 장애물 회피·범죄 판단·신원 인식·추적 주행은 제공하지 않습니다.

## 3. 실시간 관찰 보조

같은 WebRTC 연결에서 VideoChannel 영상을 받습니다.
YOLO는 별도 작업에서 최신 프레임을 분석하고, 선택한 대상의 박스만 표시합니다.
선택 대상: person, backpack, handbag, suitcase. [관찰 설정 적용] 후 반영됩니다.
모델 로딩 실패 시 실제 원본 영상은 계속 표시하며 오류를 알립니다.
원본 프레임은 최대 폭 960px, 약 10fps로 JPEG 버퍼에 수집합니다.
탐지 분석 속도는 PC 성능에 따라 달라집니다. 박스는 분석한 프레임 위에 표시합니다.
영상이 2초 이상 끊기면 현재 영상 화면을 숨기고 미수신으로 표시합니다.
배터리·실제 속도·지연 값은 아직 센서 연동하지 않았으므로 — 로 남겨둡니다.

기본 모델은 `yolo11n.pt`이며 처음 로딩 시 Ultralytics가 다운로드할 수 있습니다.
이미 있는 가중치를 쓰려면 실행 전에 지정할 수 있습니다.

```bash
export K9_YOLO_MODEL=/실제/경로/yolo11n.pt
python app.py
```

## 4. 이벤트 전후 영상 자동 저장

선택 클래스가 약 0.25초 이상 연속 관찰되면 자동 촬영합니다.
전 3초는 메모리 버퍼에서 가져오고 후 3초는 계속 수신해 수집합니다.
클래스가 2초 이상 보이지 않다가 다시 관찰되면 다음 등장으로 처리하며 최소 저장 간격도 적용합니다.
이것은 클래스별 등장 감지입니다. 다른 사람을 각각 구별하거나 동일 인물을 재식별하는 객체 추적은 아닙니다.
새 사람이 기존 사람과 동시에 등장하는 경우 별도 인물 이벤트로 나누지 않습니다.

원본 JPG, 이벤트 전후 영상, 수신 시각, 클래스·점수·박스, 실제 전후 길이를 SQLite에 연계 저장합니다.
위치는 구독하지 않으므로 미수신으로 남깁니다. 촬영 시각은 PC의 수신·기록 시각이며 센서와 정밀 동기화된 시각이 아닙니다.
시작 직후 전 구간이 부족하거나 연결이 끊겨 후 구간이 부족하면 partial과 실제 길이를 남깁니다.
수동 촬영도 같은 방식으로 전후 영상을 저장합니다. 자동 이벤트는 한 클래스의 등장당 한 번 저장합니다.
최대 4개 이벤트 수집 작업으로 메모리 사용을 제한하며 초과 시 오류를 표시합니다.

### 브라우저에서 영상 재생

ffmpeg가 있으면 MJPG AVI를 H.264 MP4로 바꿔 웹에서 재생합니다.
WSL Ubuntu에서는:

```bash
sudo apt install ffmpeg
```

ffmpeg가 없거나 변환이 실패해도 AVI 원본을 저장하며 다운로드할 수 있습니다.
카메라/디스크/인코더 오류는 저장 완료로 위장하지 않고 error로 남깁니다.

## 5. 기록 검색·관리

[기록 보관함]에서 대상, 제목·키워드·메모, 현재 활동, 자동/수동 유형으로 검색합니다.
원본 사진·영상·시각을 확인하고 메모 편집, 요약 포함/제외를 적용할 수 있습니다.
서버 검색은 키워드 및 메타데이터 검색입니다. 자유로운 자연어 검색을 LLM으로 구현한 것은 아닙니다.
메모는 기록마다 [메모 저장]을 눌러 반영합니다.
JSON 내보내기는 메타데이터만 내보냅니다. 영상도 보관하려면 data 폴더 전체를 복사하세요.
자료 위치: k9_console/data/records.sqlite3 와 data/media/.
다른 위치는 `python app.py --data /원하는/절대경로`.

## 6. 로컬 LLM 요약

Ollama가 실행되어 있고 사용할 모델이 설치돼 있어야 합니다.

```bash
ollama list
ollama serve
```

이미 Ollama가 실행 중이면 serve를 중복 실행할 필요 없습니다.
화면의 모델 이름을 `ollama list`에 표시되는 정확한 이름으로 지정합니다. 기본 입력값은 qwen3.5:4b입니다.
[로컬 LLM 요약] → [검색된 포함 기록 요약]을 누르면 검색 조건에 맞는 완료/일부 저장 기록만 사용합니다.
영상이 아니라 탐지 메타데이터와 사용자 메모를 JSON으로 전달합니다.
원본 기록 ID가 유효한지 검사하고, 유효한 응답만 DB에 저장합니다.
사용자가 사실 충실도를 검토해야 하며, ID 검사가 내용의 진실성까지 보장하지 않습니다.
100건 이내로 검색 조건을 좁혀 요청합니다. 요약 중에도 조종·영상 작업은 별도 실행됩니다.
생성된 요약은 자동 저장됩니다. 편집한 문장은 다운로드로 보관하며 편집본의 DB 저장은 제공하지 않습니다.

기본 주소는 Python 실행 환경의 http://127.0.0.1:11434 입니다.
Windows Ollama와 WSL 앱이 분리되어 있다면 해당 WSL에서 접근 가능한 Ollama 주소를 환경변수로 지정하세요.

```bash
export K9_OLLAMA_URL=http://Ollama를실행하는호스트:11434
```

이는 연결 가능한 로컬 주소 설정이며 인터넷에 Ollama를 공개하라는 안내가 아닙니다.
모델이 없거나 서비스에 접근할 수 없으면 오류만 표시하며 예시 요약으로 대체하지 않습니다.

## 7. 파일 구성

app.py: 로컬 HTTP API·영상 스트림·다운로드
controller.py: WebRTC 연결·주기적 이동·명령 갱신 제한·자세
vision.py: 카메라·YOLO·프레임 버퍼·이벤트 영상
storage.py: SQLite 기록·메모·요약 저장
summarizer.py: Ollama 요청·JSON 출력 및 원본 ID 검사
static/index.html: 기준 콘솔 기반 UI
robot/connection.py: 기존 연결 클래스

## 8. 검증 범위

확인 완료: Python/JS 문법, 실제 JPEG/영상 인코딩 및 전후 길이,
SQLite 기록 생성·검색·편집·제외, 로컬 HTTP API와 토큰/속도/미연결 검사.
LLM 응답 저장과 잘못된 출처 차단은 테스트용 응답으로 검증했습니다.
실제 로봇 WebRTC·실시간 YOLO 성능·사용자 Ollama 응답·사용자 PC 브라우저 통합은 이 환경에서 검증하지 못했습니다.
"완제품 동작 확인 완료"가 아니라 실제 연동 코드를 제공한 상태입니다.
